A. K3 byte-stride capacity
S: 896 experts/layer; gate/up dimensions 3584×3072, down 3072×3584. T: 256 elements/block; IQ1_S=50 B, IQ2_XXS=66 B (also IQ2_XS=74, IQ3_XXS=98, Q6_K=210 B; these latter types are not K3 routed groups).
Per part: 3584×3072/256=43008 blocks; IQ1_S=2150400 B; IQ2_XXS=2838528 B. S directly shows all-IQ1_S and mixed gate/up at L1/L11; K gives group counts 80/10/2.
Old stride O=ceil(record/lcm(4096,part block sizes))×lcm(...); byte stride N=ceil(record/4096)×4096. Padding below is (O-record)/O; overhead is (O-record)/record.

LCMs are 102400 B (4096,50) and 3379200 B (4096,50,66). N has zero padding for all groups. Thus “~30% mixed padding” is an approximation that hides the third group's different overhead.
Exact reconciliation: 896×(80×6451200+10×7827456+2×7139328)+12288 header B=545349709824 B, exactly S.total_bytes.

B_i≈376989449406 / 57176733160 / 10430041434 B. Total host slots 65102→67198: +2096, +3.220%, equivalent to ~13651 MiB of old capacity. This is the nominal ceiling, excluding Y's separate 24576 MiB HBM tier, valve releases, and any finer group partitioning.
