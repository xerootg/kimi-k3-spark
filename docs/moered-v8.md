# 0035 v8: singleton fused MoE merge

The concrete eligibility boundary is the host split-bank merge in `hotpath-src/src/llama-graph.cpp`: `experts = ggml_view_3d(... n_embd, n_expert_used, n_tokens, ..., merged->nb[1]*(n_expert_used + (n_tokens > 1 ? 1 : 0)), 0)`. With eight experts, consecutive token starts are eight expert rows apart at N=1 and nine rows apart at N>1. The extra row is the split merge scratch destination. The weighted MUL output is contiguous, but its expert input is not. v7 `split_mul` requires that input to be contiguous. Thus singleton split layers match the fused weighted fold while batched split layers fall back to separate MUL and ordered ADD kernels. Other layers can still fuse; disabling the class changes both runs and can make both equal. This explains why disabling weighted reduction can affect N=2 even though its split layers already fall back.

The local `llama/ggml/src/ggml-cuda/moe-weighted-reduction.cu` launches `(n_tokens, ceil(n_embd/256), 1)` blocks of 256 threads. Each thread handles one embedding component of one token and folds experts in order. It neither reduces across tokens nor changes block size for multiple tokens. Its flat indexing assumes compact expert rows: `token * n_expert_used + expert`. Passing the nine-row token stride directly would read scratch rows. The production leaf was not supplied in `evidence/c-tree`; this leaf describes the local implementation, not a verified copy of the post-update Spark binary.

Router weights are logically `[8, n_tokens]`, physically `[1, 8, n_tokens, 1]`; token stride is `weights->nb[2]`. Logits use axis 1; IDs use axis 1 with full expert-count row stride, despite their top-eight logical width. v7 already calls the original fused topk entry once per token, preserving that ID stride, clamp, scale, bias and args. Its matcher handles sigmoid/softmax/softplus patterns; launch eligibility checks supported expert count, contiguous logits/weights, and gating parameters. The memory check also gates aliasing. There is no demonstrated N=2 topk eligibility change in these predicates. Equality of two output hashes alone does not establish that topk ran unfused. v8 preserves this existing topk path byte for byte.

v8 accepts float expert views with contiguous embedding/expert axes and nonoverlapping padded token strides only when EXACT_COLS and 2..8 tokens apply. Contiguous weights, weighted outputs, ordered expert views/additions and fusion memory checks remain required. It slices experts, optional expert scales and weights by their actual token strides, constructs compact singleton metadata on the stack, and invokes the original reduction entry once per token with eight experts and one output column. The scratch row is skipped. Both token axes are supported. N=1, flag-off, class-disabled and >8 behavior is retained. The matcher uses bounded stack arrays instead of temporary vectors; replay introduces no allocations or environment reads. The full replacement includes the v7hot changes.

Tests execute extracted matcher and launcher bodies with host spies, patch reversal/reapplication and the existing hot-stack host syntax checks. They establish eligibility, pointer offsets and parameters, not CUDA rounding, graph capture behavior or final bytes. The requested 9449ae5738 gold must be checked by `win2fdr.sh` on Spark. No GPU, nvcc, model/store or fd9 tree is available here, and network access was not used.
